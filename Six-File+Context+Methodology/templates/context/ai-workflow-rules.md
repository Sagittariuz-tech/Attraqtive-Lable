# AI Workflow Rules

## Approach

Use the six context files as the source of truth. Work in verifiable storefront units and record changes to scope or interfaces in the corresponding file.

## Scoping Rules

Validate editorial shell, discovery, product, commerce, consultation and concepts in sequence. Stage B commercial integrations and Stage C providers each require owner approval and their own specifications.

## When to Split Work

Split independent routes, persistence changes, payment transitions and photo handling into units with explicit acceptance checks.

## Handling Missing Requirements

Use reversible sample fixtures and visible provenance. Track owner questions in the progress tracker. Exclude conflicting hours, directory pricing, unofficial social accounts and unapproved policies from client-facing claims.

## Protected Files

Preserve the source business brief and methodology guide. Keep installation artifacts and generated framework files out of source control. Keep credentials and private content outside the application repository.

## Keeping Docs in Sync

Update the context that owns the decision and record verified progress after each meaningful unit.

## Before Moving to the Next Unit

Check the route from its normal entry point, validate affected business rules, run appropriate lint/type/build or browser checks and record outstanding work.
